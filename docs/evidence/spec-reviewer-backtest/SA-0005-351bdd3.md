**SA-0005 spec review** (`.saffron/specs/SA-0005-size-wiring.md` at HEAD)

The spec has four blockers. Two criteria need files that aren't in `touches`, and it declares no witnesses or mutants.

## Findings

- **Blocker: `saffron/phases/package.py`, which criteria 2 and 6 require, is not in `touches`.** Criterion 6 (spec:62–63) says "The effective tier, not `spec.risk`, is what the PR body header and the queue line report". But the queue line is built in package.py:775 (`risk=spec.risk,`). The header is rendered from `spec` at package.py:662–678, and pr_body.py:74 reads `` risk `{spec.risk}` ``. For either to show the effective tier, `package()` has to pass it through from `CellOutcome`. Criterion 2 (spec:54–55) says `size` "appears in every gate result set and in the PR body's gate table". When the base has moved, package.py:623–637 swaps the gate table's input for `reverify`'s results, and those come from `runner.run_suite` with declared gates only (package.py:467–471). So `size` never reaches the table on that path. **Fix:** add `saffron/phases/package.py` and `tests/test_package.py` to `touches`. Otherwise, move the reverify path of criterion 2 out of scope.

- **Blocker: `saffron/cli.py` is not in `touches`, so a spec's own `risk:` never reaches the session.** Criterion 1 (spec:50–51) needs "`elevated` when the spec says so". But `CellSpec` has no `risk` field (session.py:149–161), and cli.py:121–132 builds it without one. A cell can add the field in session.py, but it will always hold its default. A `risk: elevated` spec that touches no `elevate_on` path would then run at `standard`. **Fix:** add `saffron/cli.py` to `touches` (one line, `risk=spec.risk`).

- **Blocker: no `witness` or `mutant` is declared for any criterion** (frontmatter spec:1–23), even though the change edits existing code. Plausible wrong implementations that pass the four tests criterion 8 asks for:
  - **Criterion 3:** filtering advisory failures only inside `repair_loop`. `_rebut_gates` still calls `subtract_baseline` directly (session.py:927) and returns `"EXHAUSTED" if new else None` (session.py:929). A `standard` task whose post-REBUT gate re-run still has the advisory `size` fail ends `EXHAUSTED`.
  - **Criterion 7:** no test is required at all. One plausible mutant errors on any `Binary files` section, ignoring `touches`. That contradicts `integrity`, which skips undeclared files (integrity.py:243–244 `if not declared: continue`).
  - **Criteria 5 and 6:** no test is required. One plausible mutant reports the effective tier in the header while the queue line keeps `spec.risk`.
  - **Criterion 1:** a witness like `saffron/cell/x.py` against `saffron/cell/**` also passes with `fnmatch`, which spec:80–81 forbids. It needs a case where `*` must not cross a `/`.

  **Fix:** declare a witness and a mutant for each criterion.

- **Blocker: one criterion-8 witness already passes at base.** "a `size` fail not repairing at `standard`" (spec:69) is already true at base, trivially: `size` never runs there (session.py:623–634). A `_drive` test with an oversized patch and no repair turn goes green at base. **Fix:** the witness must also assert that `outcome.gates` holds `size` with status `fail`, and that the state is `READY_FOR_REVIEW` with no repair turn.

- **Concern: criterion 7's `error` aborts at a tier where `size` is advisory.** CONTEXT.md:223–224 says advisory gates "are reported in the PR body and stop nothing". CLAUDE.md says `error` "aborts the attempt", and `aborted_gates` (session.py:189–192) aborts on any `error`, whatever the tier. So a binary fixture inside `touches` turns a `standard` task into `GATE_ERROR`. The spec's reasoning covers only `elevated` ("zeroes the gate at the one tier where it blocks", spec:66–67). The same question applies to a `blocking: false` declared gate that errors, including at baseline (`PREFLIGHT_FAILED`, session.py:648–659). In this repo `integrity` already errors on the same diff (integrity.py:242–252). In a repo with no integrity patterns, `integrity` skips (integrity.py:211–216), so this abort would be new. You need to decide which invariant wins and write it into the spec.

- **Concern: criterion 5 says "wherever it is rendered", but the critic's prompt is outside `touches`.** `review.gate_summary` (review.py:103–107) renders `- {r.gate}: {r.status} ({r.tool or 'no tool reported'})` into every lens prompt (session.py:874). An unmarked `size: fail` on a green diff invites a lens to raise it as a blocker. **Fix:** add `saffron/phases/review.py` to `touches`, or limit criterion 5 to the PR body.

- **Concern: reverify treats advisory failures as blocking.** At package.py:638–656, any new failure after a rebase becomes `MERGE_FAILED`, so a `blocking: false` gate stops packaging. That contradicts criterion 4 ("behaves the same way at every tier — reported, never repaired"), and the spec says nothing about it.

- **Concern: the ledger's risk column stays `standard`.** `create_task` is called without `risk` (session.py:525–531), so `tasks.risk` defaults to `'standard'` (ledger.py:42, 246). `ledger.queue_lines` reads `t.risk` (ledger.py:453). If "the queue line" includes the ledger's, then ledger.py is needed, and it is itself an `elevate_on` path (.saffron/policy.yaml:13). Clarify which queue line the spec means.

- **Concern: ceilings cannot be checked.** The only history row is SA-0005 itself, with no peak, spend or outcome. Also, `saffron cell` does not read the spec's `budget_usd`: it uses `--budget` (default 12.0, cli.py:64, passed at cli.py:130). The spec sets no `max_turns`, so the cell runs at the default of 60 (session.py:161). Whether the driver passes `--budget 12` is **unverified**.

- **Note:** `render_pr_body` has a second caller at replay.py:116–126. Any new tier parameter must be optional, or replay.py (outside `touches`) breaks.

- **Note:** spec:34–35 says both declarations are "tested at the policy layer". `blocking` is (test_policy.py:45–46). `elevate_on`'s value appears in a fixture (test_policy.py:15–16) but is never asserted.
