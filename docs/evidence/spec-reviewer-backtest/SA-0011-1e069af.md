- **Blocker: a spec that opts in takes its criteria away from the critic.** DESIGN.md:230 says: "Acceptance criteria are checkboxes because … the critic is handed them as its rubric."
  - **Why:** the spec makes `acceptance:` and the markdown `## Acceptance criteria` section mutually exclusive (spec:198-200, criterion 11). But the critic's prompts receive only `spec.body`: `review.py:131` (`spec=spec_body`), `rebut.py:250`, fed from `session.py:959` and `:1029`. So a spec that declares `acceptance:` gives REVIEW and the REBUT verdict no criteria at all. The contract lens still tells the critic to hunt for "an acceptance criterion technically satisfied but not actually met" (`review-contract.md:16`).
  - **IMPLEMENT too:** criterion 10 only requires the *witnesses* to reach the IMPLEMENT prompt, so the implementer can get test names without the claims they stand for.
  - **Fix:** add a criterion that each `claim` and its `witness` reach the IMPLEMENT, REVIEW and REBUT-verdict prompts. `session.py` can append a rendered acceptance block to the `spec`/`spec_body` it passes at `:745`, `:959` and `:1029`. That file is already in `touches`, so `review.py` and `rebut.py` need no edit.

- **Blocker: no criterion requires the gate to run in production.** The check-3 rule: a wrong implementation the witnesses would pass is a blocker.
  - **Why:** none of the 14 criteria says `criteria_gate` must be called from `_suite` (`session.py:703`, where `census` is called), or that `cli.py:176-187` must pass the declared criteria into `CellSpec` (`session.py:150-171`, which has no such field).
  - **The wrong implementation:** build and unit-test the gate, intake and `pr_body`, and never wire any of it. Every criterion's natural test passes, and in production `criteria` never runs, so no box is ever ticked.
  - **Precedent:** the repo has already been bitten by this. `test_session.py:1086-1090` says: "Both tests below call `census_gate` directly, so both stayed green under two mutations that make the branch's whole purpose vanish."
  - **Fix:** add a criterion that a witness failing at head reaches the agent as a `criteria` failure through `_drive_cell`, modelled on `test_session.py:1081-1136`. It should exercise both the `cli` → `CellSpec` handoff and the `_suite` call.

- **Concern: re-verification drops the gate result, and the spec doesn't say what the PR body does then.** `package.py:624-638` swaps `outcome.gates` for `reverify`'s results when the base has moved. `reverify` runs only the declared gates (`package.py:468-472`), so there is no `criteria` result (or `census`, already). The same is true of `replay.py:116-118`.
  - Criteria 12 and 13 cover "ticked from a result" and "`skip`", but not "no result at all". `package.py` is not in `touches`.
  - **Fix:** say explicitly that a missing `criteria` result renders the same as `skip` ("not mechanically checked"). That is honest and stays inside `pr_body.py`.

- **Concern: a ticked box doesn't quite mean what the spec says it means.** The spec says a tick means "a test by this name ran at head and passed" (spec:82-83), but `W ∈ collected ∧ W ∉ {f.code}` only shows "collected and not listed as failed".
