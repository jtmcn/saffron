# SA-0040 spec review: not runnable at this base

Two blockers. First, the spec depends on SA-0029's `saffron/events.py`, which is not in the base. Second, nothing checks `describe` against the lines the code really prints.

## Findings

- **Blocker — the spec builds on a module that doesn't exist at base.** The spec says "`SA-0029` shipped `saffron/events.py` — nine frozen dataclasses, the `Event` union, `EventLog` and `read_log`" (SA-0040:35–36). At base:
  - Reading `saffron/events.py` returns "File does not exist", and so does `tests/test_events.py`.
  - The only tracked path matching "event" is `.saffron/specs/SA-0029-the-host-has-no-event-vocabulary.md`. It sits in `specs/`, not `specs/done/`, and SA-0029 has no row in `history`.

  A cell run directly with `saffron cell` stacks only on a parent that has a waiting ledger row. "A parent merged, retired, dead, unrun, or never in the ledger at all has no such row" (cli.py:250–251), and in that case `if not waiting: return None, None` (cli.py:284–285), so the cell is cut from this base. The agent would then have to write SA-0029's nine dataclasses and `EventLog` as well as this spec's work, all inside 600 lines. That is the 1100-line plan that was rejected at $2.20 (SA-0040:45–47). Criteria 1 and 2 both depend on the nine kinds existing, so they fall too. Through `saffron queue`, the scheduler refuses the spec instead: "depends_on {dep} has no task at its current spec_sha" (scheduler.py:511–514).

  Whether SA-0029 has a waiting task with a pushed branch in `~/.saffron/ledger.db` is **unverified**; I can't read the ledger.

  **Fix:** don't run SA-0040 until SA-0029 is in a waiting state with a pushed branch. Then review it again with SA-0029's branch as the base, because the fit of the nine kinds is exactly what this spec tests.

- **Blocker — no test ties `describe` to the lines the code really prints (check 3).** The spec edits `events.py` (a file that exists once SA-0029 lands) and declares no mutant. Criterion 1 needs `describe(event)` to return "the exact line today's `watch` call site would have printed" (SA-0040:65–66), but none of its tests compare `describe` output with those lines:
  - Criterion 3's golden test compares `run_one_cell`'s output with the fixture (SA-0040:78–79). That output comes from the unchanged `watch` f-strings; it never goes through `describe`.
  - Criterion 2's test asserts only that each family "has a kind and renders" (SA-0040:72–73).

  Two wrong implementations would pass every test here:
  - A `Budget` rendering that uses an ASCII hyphen where `session.py:1048` prints `f"budget: ${spent:.2f} of ${spec.budget_usd:.2f} — stopping"` with an em dash.
  - A `PhaseStart(phase, detail: str)` that absorbs every awkward family. The spec admits this itself: a `message: str` "would pass every test here" (SA-0040:148–150).

  SA-0030 would find either defect against a blocking gate.

  **Fix:** add two criteria.
  - For each fixture line, a test builds the event that the mapping table says carries it and asserts `describe(event) == line`.
  - For families the fixture doesn't cover, a parametrised test with expected strings copied from each call site's f-string, filled in with fixed values.
