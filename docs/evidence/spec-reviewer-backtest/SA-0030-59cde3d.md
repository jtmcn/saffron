I found four blockers and three concerns. The biggest problem is that criterion 1, "every `watch(...)` becomes an `emit(<Event>)`", can't be met without a type lie, and the golden test depends on it. Criteria 2, 5 and 6 also contradict each other.

## Findings

- **Blocker — session.py:1415 and :1433–1439: the outcome line and the rate-limit line have no event kind.**
  - **What breaks:** criterion 1, "Every `watch(...)` in `saffron/cell/session.py` is an `emit(<Event>)`" (spec:59), together with criterion 2, which needs golden lines 16 and 33 (`READY_FOR_REVIEW: $0.40 spent, session sess-1`, `EXHAUSTED: …`) to come out of the migrated code.
  - **Why no kind fits:** `events.FINDINGS[0]` (events.py:648–657) says these two lines need "a tenth kind, out of scope here". The spec forbids a tenth kind ("not a tenth dataclass added here", spec:101–104) and forbids `events.py`. It also claims `SA-0040` "proved it covers all 64 call sites" (spec:102), which is false by that FINDINGS entry.
  - **Why no workaround passes gates:**
    - The only kind that renders arbitrary text is `PhaseStart` (`f"{event.label}: {event.detail}"`, events.py:484). But its `label` is the `LineLabel` Literal (events.py:63–73), and that excludes `READY_FOR_REVIEW`, `EXHAUSTED` and `rate limit`.
    - The `types` gate is `{ blocking: true }` (.saffron/policy.yaml).
    - Silencing the checker with a `ty` ignore comment is on the `integrity` suppressions list.
    - The rate-limit line can't be forced into `Budget` either: that renders `budget: … — stopping` (events.py:511), and it would blur "`RATE_LIMITED` is not `EXHAUSTED`" (CLAUDE.md).
  - **Fix:** exempt the two `FINDINGS[0]` sites from criterion 1 (they stay as prose and are named in the PR body). Say how they reach the terminal and the `_drive` capture, since criterion 1 also removes every `watch` parameter.

- **Blocker — the `GateResult` event: criteria 2, 5 and 6 can't all hold.**
  - **The criteria:** criterion 6 (spec:80–81) requires "A gate result event carries `error` distinctly from `fail`", recorded from a driven attempt. Criterion 2 (spec:61–63) says the printed output equals the fixture. Criterion 5 (spec:78–79) says `read_log` returns "the same sequence the terminal printed".
  - **Why they clash:**
    - `describe(GateResult)` renders `gates: {gate}={status}` (events.py:508), and "No call site prints one alone today" (events.py:503).
    - The fixture has no such line; test_events.py:843 says "`GateResult` entirely … this file proves nothing about it".
    - So if the default fan-out renders `GateResult`, the golden test breaks. If it skips them, the log holds events the terminal never printed, which breaks criterion 5, and a filtering renderer is out of scope ("Any renderer", spec:101).
    - Criterion 6 can't fall back on `Attempt` either: `Attempt.aborted` is gate names, not a status (events.py:169).
  - **Fix:** say that `GateResult` events go to the log only and are not rendered. Reword criterion 5 as "the log's rendered, non-`GateResult` events equal the printed lines".

- **Blocker — session.py:652–653 and :875: an unwritable `task_dir` raises before any terminal state is reached.**
  - **The criterion:** "a test makes `task_dir` unwritable and asserts the session still reaches its terminal state" (spec:82–83).
  - **Why it can't pass:** `task_dir` also holds real artifacts, written before any `EventLog` question arises.
    - The policy export `export_saffron_dir(mirror, spec.base_sha, task_dir / "gates")` runs *above* the `try` ("Hoisted above the try", session.py:640–653). The test stub copies files into that directory (test_session.py:824–832).
    - `baseline.json` is written at :875.
    - An unwritable directory therefore raises, and the only reachable result is `ORPHANED` plus a re-raise (session.py:1456–1466).
  - **Consequence:** a cell either can't pass this test, or writes one that passes vacuously: `pytest.raises` passes just as well when a broken `emit` raises.
  - **Fix:** make only `events.jsonl` unwritable (for example, pre-create it as a directory). Then assert that `READY_FOR_REVIEW` is reached, the lines are printed, and `EventLog.failed is True`.

- **Blocker — no `mutant` for any criterion, and wrong implementations pass the stated tests.** issue-tracker.md:12–14 lists no `witness`/`mutant`/`preserves` fields, and this spec declares none, though it edits existing code. Wrong implementations that would pass:
  - **Criterion 4:** a default `emit = lambda e: print(describe(e))` that never builds an `EventLog` passes "asserts it still prints". Criterion 5 won't catch it: a test built on `_drive` passes its own `emit=`, so the default never runs.
  - **Criterion 7:** an `emit` that never writes the log passes. So does one wrapped in `except Exception: pass`, which events.py:326–329 explicitly rejects ("narrower than bare `Exception` so a programming error … still surfaces").
  - **Criterion 8:** "a test asserts the seam between them is intact" names no observable property.
  - **Fix:** add a mutant per criterion. For example, "default emit without the `EventLog`" must fail a test that captures stdout and calls `run_one_cell` with no `emit`. "Swallowing emit" must fail a test that makes `describe` raise.

- **Concern — spec:125–127, the phase adapter's direction is unstated and only one direction passes.**
  - **Why only one works:** golden lines 13–14 (`REVIEW: correctness: …`) are printed by `phases/review.py:run_review` (events.py:621). With no `watch` left on any session.py signature, the only sink `_drive` can hand in is `emit`. So the adapter has to parse phase prose back into Events: `PhaseStart` by prefix, `Agent(detail=…)` with `agent: ` stripped (events.py:518).
  - **The trap:** an adapter that prints directly drops those lines from `cell.watched` and fails criterion 2.
  - **Fix:** say which conversion is sanctioned.

- **Concern — budget and turn ceilings, compared against the sibling spec rather than `history`.** The plan sizes `SA-0031` (15 sites) at `budget_usd: 18`, `max_turns: 140` (docs/superpowers/plans/2026-08-31-operator-visibility.md:894–896). This spec migrates 47 sites at 14 and 120. One data point: `SA-0040`'s rebuttal alone cost $2.59 (same file:1303). This is **unverified** against real cell rows.

- **Note — spec:69–71:** "`_drive` and `_stub_the_runtime`, which pass `watch=` today" is half false. Only `_drive` does (test_session.py:888); `_stub_the_runtime` (656–789) takes no `watch`. Separately, spec:44 says "11 keyword sites" pass `watch` into the phases, but one of them (session.py:602) is `run_one_cell` → `_drive_cell`, not a phase call.
