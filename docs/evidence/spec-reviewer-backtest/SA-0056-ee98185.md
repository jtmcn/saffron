I found two blockers in SA-0056. Both are fixed by rewording a claim, so the spec is runnable once they are fixed. Neither is a scope or budget problem: they are witnesses that a plausible wrong implementation would pass. That matters twice over here, because this spec cannot declare mutants of its own, and SA-0057 forbids `saffron/mutation.py` (SA-0057:20). Whatever API this cell ships is the one SA-0057 has to use.

## Findings

- **Blocker: the byte-identical witness can be vacuous, and restore is the part left unspecified.** Criterion 3 (spec:44-48) says "Restoring is the caller's obligation and the applier's promise", and only requires `apply` to return "the exact bytes it displaced". Criterion 6 (spec:63-66) then claims apply-then-restore leaves the file byte-identical.
  - **Wrong implementation the witnesses pass:** `apply` returns only `find`, with no offset, and restore swaps `replace` back to `find`. That breaks when `replace` is `""` (a deletion mutant), or when the `replace` text already appears elsewhere in the file. On a simple fixture both `test_applying_a_mutant_returns_what_it_displaced` and `test_apply_then_restore_is_byte_identical` still pass.
  - **Vacuous shape:** since restore is "the caller's", the witness can save the file's bytes before `apply`, write them back itself and compare. That passes whatever `apply` returns. It is the "test that constructs the value it then asserts" pattern (DESIGN.md:955), in the spec meant to stop it.
  - **Line endings:** a `read_text`/`write_text` implementation turns CRLF into LF on POSIX and still passes an LF-only fixture.
  - **Why it binds:** SA-0057:84-85 relies on "an applier that can put a file back exactly as it found it", and SA-0057 cannot edit `mutation.py`.
  - **Fix:** put `restore` in `saffron/mutation.py` and have it use only what `apply` returned (the original bytes, or offset plus displaced text). Require the witness to restore with that and nothing else. Name the fixtures in the claim: CRLF, no trailing newline, `replace: ""`, and a `replace` that already occurs elsewhere in the file.

- **Blocker: the containment witness passes an implementation that only checks `..`.** Criterion 7 (spec:67-72) says "A mutant may not name a path outside the tree". Its rationale names only `..`, and adds "the applier refuses it rather than resolving it".
  - **Wrong implementation the witness passes:** `if ".." in Path(file).parts: refuse`. It passes a `../x` witness, but an absolute `file: /etc/x` still escapes, because `tree / "/etc/x"` is `/etc/x`. That is pathlib behaviour I did not re-run here (**unverified**).
  - **Symlinks:** "rather than resolving it" steers the implementer away from `resolve().is_relative_to(tree)`, the check that also catches a symlink the diff plants inside the tree. The diff is written by an untrusted cell.
  - **What I could not confirm:** the worktree lives on a cell volume (worktree.py:1, "on a volume mounted at /work"). Whether the gate's writes land on the host depends on where SA-0057 runs the applier (**unverified**), so I claim no host compromise.
  - **Fix:** say that absolute paths are refused, and that containment is checked on the resolved path, symlinks included (or that symlinks are refused outright). The witness should cover `..`, an absolute path and an in-tree symlink that points outside.

- **Concern: a no-op mutant is accepted, and it would fail a sound witness.** Criterion 2 (spec:38-42) refuses only a missing file or an empty `find`. A mutant with `replace == find` (an operator slip) changes nothing, so every witness "survives" it. SA-0057:39-44 treats a survivor as `fail`, and it is blocking at `elevated` (DESIGN.md:925). Fix: refuse `replace == find` at parse too.
  - Relatedly, `Mutant` should use `extra="forbid"` as `Criterion` does (intake.py:51). Otherwise, if `replace` defaults to `""`, a typo such as `replce:` silently becomes a deletion mutant.

- **Concern: a claim in the spec is false.** Spec:129-130 says "every spec in this repo is retired". At base, `.saffron/specs/` holds SA-0056, SA-0057 and SA-0058, none of them under `done/`. No criterion depends on it: the point it supports, that no spec declares a `mutant:`, is true (no match for `mutant:` anywhere under `.saffron/specs`). Fix: reword it to "no spec in this repo declares one".

- **Note: declaring no mutants is justified.** The spec edits `saffron/intake.py` yet declares none. That is correct: `Criterion` forbids extra keys at base (intake.py:51, `extra="forbid"`), and specs are parsed on the host by the installed code (cli.py:403 `load_spec(args.spec)`; batch export at cli.py:756). Spec:97-102 gives the reason, and it holds.

- **Note: `depends_on` is missing from the frontmatter.** docs/agents/issue-tracker.md:12-14 says every field is required ("the parser gates on all of them"), but intake.py:74 defaults it, so the spec parses. Using `acceptance:` with no `## Acceptance criteria` section is the sanctioned form (intake.py:120-126).

- **Note: "byte-identical" is fine here.** CONTEXT.md:288 lists "byte-identical" under _Avoid_, but only for no-progress. The code already uses it literally about file bytes (pr_body.py:316), and this spec does the same.
