**Findings**

1. **Blocker: undoing with `git checkout HEAD` wipes the agent's uncommitted work.** Spec line 44–46 says: "The agent's work is committed by the time gates run — `committed` is what guarantees it". That is false at base.
   - `witness` runs inside `declared = run_suite(..., mutate=...)` (session.py:1004–1010). `committed = committed_gate(worktree.dirty_paths(container))` is computed after it (session.py:1045) and only reports. committed.py:5–7 says so: "an uncommitted change is live for every gate".
   - revert refused exactly this at revert.py:174–179: "an uncommitted edit to a source path does not survive this gate — and `committed` runs next and would report the tree clean … Refusing to run is the only honest answer".
   - Built as written, `git checkout HEAD -- <file>` destroys uncommitted edits in `mutant.file` and hides them from `committed`.
   - Claim 2's witness (`…restores_the_committed_file_not_a_byte_copy`) can only tell a HEAD restore from a byte restore when the file differs from HEAD before the mutant goes in. That means the witness has to assert the destruction.
   - A second failure: if `mutant.file` is untracked or absent at HEAD, the checkout fails and leaves the tree mutated. worktree.py:273–276 measured this ("requires *every* pathspec to exist in `HEAD`").
   - **Fix:** before writing, if `mutant.file` is dirty (`git status --porcelain -- <file>`) or not in HEAD (`_exists_at(container, "HEAD", file)`), yield a reason (giving `skip`) and write nothing. Rewrite claim 2 as "HEAD is what a *clean, tracked* file returns to", and point its witness at that refusal.

2. **Blocker: the spec edits existing code but no criterion declares a `mutant`.** For three criteria, a plausible wrong implementation would pass the named witness:
   - **C3:** applying the first of several matches (`text.replace(find, replace, 1)`) passes a witness that only checks zero matches. Mutant: `count != 1` → `count == 0`.
   - **C4:** an entry that writes, then fails the exec and raises without undoing, passes a witness named for the *undo* only. witness.py:78–85 names this exact case: "a container exec that applies the edit and then loses the connection is exactly the shape that is not".
   - **C5:** keeping `stub_mutator` on the baseline call and supplying the real one only at head.
   - The operator chose this deliberately (spec:100–103). While this cell runs, the host still supplies `stub_mutator` (session.py:1009), so a declared mutant would just `skip` this time. Adding them costs almost nothing, but it makes C5's "Every spec in this repo declares no mutants" false, so that sentence needs rewording too.

3. **Concern: C4 contradicts `witness_gate`.** C4 (spec:55–56) says a failure "raises … and the gate turns that into `skip` or `error`". But witness.py:164–187 turns *every* raise into `error`; `skip` only comes from a yielded reason (witness.py:65–70, 145–147).
   - Read literally, "a failure to apply raises" means a find with no match or several matches becomes an `error`.
   - That aborts the attempt (`aborted_gates`, session.py:296–299). It also contradicts C3 and DESIGN.md:919–921 ("reports `skip` for a criterion whose `find` text is absent or matches more than once").
   - **Fix:** a mismatched `find` yields a reason (`skip`); an exec that fails on apply or undo raises (`error`). Also require an entry that may have written to undo before it raises.

4. **Concern: the spec never says how the find/replace gets into the cell, and the obvious route leaves `touches`.**
   - `runtime.exec_` takes no stdin (runtime.py:269–281), and git cannot do a literal exactly-once replace. Spec:92–93 says "None of the byte-level machinery needs to cross into the container", but the apply half has to run there.
   - A cell that adds stdin to `exec_` edits `saffron/cell/runtime.py`, which is outside `touches`, so `scope` fails.
   - The option that stays in scope is argv to `/opt/saffron/python` (images/cell-base.python.Dockerfile:38–42; phases/implement.py:33). That base image calls itself "agent runtime and git. Nothing else" (line 1), so using it is an operator call under §2.1.
   - The host test seam `_host_git` (tests/test_worktree.py:765–769) runs argv on the host, where `/opt/saffron/python` does not exist.
   - **Fix:** name the mechanism in the spec, or add `saffron/cell/runtime.py` to `touches`.

5. **Concern: deleting the stub fails `census`.** "This replaces the stub" (spec:73) reads as deleting `stub_mutator`.
   - `test_the_stub_mutator_makes_the_result_an_honest_skip` (tests/test_session.py:3147, which calls `session.stub_mutator` at :3162) would then have to go.
   - `census` fails on any removed test and has no override (census.py:34–38, 72–91).
   - It would also make forbidden mutation.py:224 ("`SA-0061`'s stub lives in `session.py`") false.
   - **Fix:** say that the stub and that test stay, or that the test keeps its name.

6. **Concern: the "wrong reason" for today's `skip` is false at base.** Spec:77–78 says "every `witness` result is `skip` for the wrong reason", and C5 contrasts this with "the previous `skip`".
