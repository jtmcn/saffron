# Spec review: SA-0019 (nothing records whether a task merged) at `HEAD`

## Findings

- **Blocker: the fixture the spec requires is not available inside a cell.** Criterion 6 (spec:86-88) says *"The fixture is this repository's own six recorded tasks and their real pull request states"*, and criterion 7 (spec:89-90) asks for *"the measurement above rather than a restatement of it"*. But spec:43-53 gives only the query plus a prose restatement (*"returns six rows, every one `READY_FOR_REVIEW`"*). The rows themselves (task_id, spec_id, spec_sha, pr_url) and the `gh` output are not there.
  - The cell cannot fetch them. The ledger is host-side (`CLAUDE.md`: *"`~/.saffron/ledger.db` … the audit trail"*), and `tests/conftest.py:13` blocks `gh` in tests (`FORBIDDEN_EXECS = frozenset({runtime.RUNTIME, "gh"})`).
  - The repo holds only two scraps: the #51 URL (`docs/evidence/2026-08-28-attach-order-takes-the-proxys-route.md:93`, `github.com/jtmcn/saffron/pull/51`) and #56 → `SA-0014` (`docs/BACKLOG.md:1373`).
  - So the agent has to invent four rows' identities, their spec_shas, and the JSON `gh` returns. That is the invented fixture spec:125-126 forbids, and the critic can fairly block on it.
  - **Fix:** paste the six rows verbatim, plus each PR's `gh pr view --json state,reviewDecision` output, into the spec.

- **Blocker: no witnesses and no mutants, and the spec's own named test passes the failure it warns about.** The spec edits existing code (`saffron/cli.py`, `saffron/ledger.py`) but has no `acceptance:` block (frontmatter spec:1-27; only SA-0011/12/13 declare one). So `criteria` reports `skip` and every box renders *not mechanically checked* (`DESIGN.md:821`).
  - spec:128-129 names the test that matters as *"asserting five of them reach `MERGED` while #65 does not move"*. Its fake `gh` always answers, so three wrong implementations pass it:
    - (a) mapping a failed or unparseable `gh` answer to `REJECTED`. This is exactly the defect spec:113-118 calls *"catastrophic for a writer"*.
    - (b) never producing `REJECTED` or `CHANGES_REQUESTED` at all. The fixture is *"five merged, one open"*, so neither state appears.
    - (c) `_queue` reconciling after `build_queue` rather than before (criterion 5).
  - **Fix:** add an `acceptance:` block with a new `tests/test_reconcile.py` witness per criterion, each paired with a mutant from (a)–(c). For example, a witness that a `gh` exiting non-zero or printing garbage leaves all six rows unchanged and reports 6 unasked.

- **Blocker: a sentence outside `touches` becomes false.** Criterion 5 (spec:84-85: *"`saffron queue` reconciles before it scans"*) and criterion 4 (the `ORPHANED` stamping) make `queue` write to the ledger.
  - `CLAUDE.md:46` says: *"`uv run saffron queue --repo .` # v0.5: what a batch would run; writes nothing"*. `CLAUDE.md` is not in `touches` (spec:7-13).
  - The spec also reverses a merged criterion without saying so: `.saffron/specs/SA-0017-saffron-queue-prints-it.md:53-55` reads *"A test asserts that `saffron queue` writes nothing at all — … no state change, no `ORPHANED` stamp"*. `.saffron/**` is forbidden, so that text cannot be edited.
  - `tests/test_cli.py:464-471` (named `…writes_nothing_to_the_ledger`, docstring *"`saffron queue` reads, it never writes"*) and `cli.py:223-224` (*"without … writing anything to the ledger"*) are in `touches`, but the spec never says to rewrite them.
  - **Fix:** add `CLAUDE.md` to `touches`. State that this spec supersedes SA-0017's criterion 4, and that the `test_cli.py:464` test is to be renamed to "an unseen repo stays unseen", not deleted.

- **Concern: `queue` or `reconcile` can stamp a live cell `ORPHANED`.** Criterion 4 (spec:81-83) is unconditional. Its rationale, `DESIGN.md:373` (*"one batch runs at a time, so nothing is legitimately in flight when a scan happens"*), is about a batch scan.
  - Today `saffron cell` and `saffron queue` are separate attended commands (`CLAUDE.md:44-46`). A scan run mid-cell stamps the live task.
  - `ledger.py:311-317` then records `phase = t.state`, i.e. `ORPHANED`, on every attempt opened until the session's next `set_task_state` (`session.py:933`, `981`, `1024`). That mislabels REVIEWING lens rows.
  - `runs.status` cannot tell live from dead: a power cut leaves it `'RUNNING'` too (`ledger.py:266`).
  - **Decide:** accept this, or limit stamping to `saffron reconcile` and document "run it with no cell alive".

- **Concern: an open, approved PR has no mapping.** Criterion 1 (spec:71-74) covers merged, closed, changes-requested, and *"open and undecided"*. §3.3's `APPROVED` arrow (`DESIGN.md:257`) is in `DONE_STATES` (`scheduler.py:46`), but the spec never says whether "approved" counts as "undecided" or should write `APPROVED`. A critic will argue about it. Say which.

- **Concern: exit codes are not specified.** Criterion 2 (spec:75-78) asks for a count but gives no exit code. `CLAUDE.md` says *"Exit codes are load-bearing"*.
  - Anything raised reaches `cli.py:99-106` and exits `2`.
  - `queue` must not exit `2` without `gh` (`cli.py:276-277`, pinned by `tests/test_cli.py:577-597`).
  - **Fix:** state that `saffron reconcile` exits `0` (or `2`) when it could not ask, and that `queue` stays `0`.

- **Concern: "never moves backwards" defines no order.** Criterion 3 (spec:79-80) names only `MERGED`. It leaves open:
  - whether a reopened-then-merged PR takes `REJECTED` → `MERGED`;
  - whether `CHANGES_REQUESTED` → `REJECTED` is allowed;
  - whether `EXHAUSTED`, `MERGE_FAILED` or `ORPHANED` rows that carry a pr_url are eligible at all.
  - **Fix:** list the source states `reconcile` may move, and the terminal ones it never touches.

- **Concern: the spec's own query selects empty `pr_url`s.** `PackageResult.pr_url` defaults to `""` (`saffron/phases/package.py:492`), and `_finish` writes it for every `MERGE_FAILED` (`package.py:766-772`). The spec's query uses `where pr_url is not null` (spec:46).
  - A `reconcile` that copies that filter asks `gh` about `""` on every run and reports those tasks as unasked forever.
  - **Fix:** specify `pr_url IS NOT NULL AND pr_url <> ''`.

- **Concern: the diff will land close to a blocking size ceiling.** `risk: elevated` (spec:26) makes `size` blocking (`saffron/gates/core/size.py:5`: *"Advisory at `risk: standard` and blocking at `elevated`"*), and the feature ceiling is 600 (`size.py:25`). - **Concern: several statements about current code are false** (no criterion depends on them strictly):
