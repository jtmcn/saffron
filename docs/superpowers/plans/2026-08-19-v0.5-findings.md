1. The brief's `tests/test_saffron_gates.py` called

   accepted it as written.
2. `.saffron/gates/format`'s brief-given `sed` pattern
   (`s/^Would reformat: \(.*\)$/\1/p`) matches an older ruff CLI. The
   installed `ruff 0.16.3` emits `  --> path:line:col` hunks instead, so the
   gate parsed zero files on a real formatting failure and reported `error`
   (correctly refusing to claim `pass`, per rule 2 — but not useful).
   Rewrote the extraction to match `--> path:...` and dedupe repeated hunks
   per file.

Also hardened `lint.py`/`tests.py`: the brief's code checked
`version.returncode != 0` to detect a missing tool, but `subprocess.run`
raises `FileNotFoundError` when the binary doesn't exist at all rather than
returning nonzero — an uncaught exception, not the intended clean
`"ruff not on PATH"` JSON. The runner's own defenses (rule 2: nonzero exit
with no parsed failures) already turned the resulting empty stdout into
`error`, never a false `pass`, so this was never a false-green risk — just a
worse error message than intended. Wrapped both version checks in
`try/except FileNotFoundError` so the gate emits its own clean message.
